# 🌱 Database Seeding Guide

## 📋 Три варианта seed'ов

### **1️⃣ Production Seed (Только товары)**

**Файл:** `prisma/seed-production.ts`
**Использование:** Подготовка к развёртыванию на продакшене

```bash
npm run seed:production
```

**Что происходит:**

- ✅ Загружает все товары (магниты и тарелки) из `public/magnets.json` и `public/plates.json`
- ✅ Сохраняет все существующие партнёров, цены и заказы
- ❌ Не создаёт тестовые данные
- ❌ Не добавляет демо-заказы

**Результат:** Чистая БД, готовая для реальных данных

---

### **2️⃣ Production Mode (Товары + Базовые партнёры и цены)**

**Файл:** `prisma/seed.ts` в режиме `production`
**Использование:** Для первой инициализации БД перед продакшеном

```bash
npm run seed
```

**Что происходит:**

- ✅ Загружает все товары
- ✅ Создаёт 3 базовых партнёра (MagnetPlus, ArtDecor, CasaSuvenir)
- ✅ Устанавливает базовые цены для всех типов/материалов
- ❌ Не создаёт заказы
- ✅ costPrice групп товаров (мрамор/дерево) задаётся сразу в `seedGroups()`

**Результат:** БД готова к использованию с базовыми партнёрами

---

### **3️⃣ Demo Mode (Полная симуляция с тестовыми данными)**

**Файл:** `prisma/seed.ts` в режиме `demo`
**Использование:** Для тестирования админ панели и графиков

```bash
npm run seed:demo
```

**Что происходит:**

- ✅ Загружает все товары
- ✅ Создаёт 5 партнёров
- ✅ Устанавливает цены
- ✅ Генерирует **50-100 рандомных заказов** за последние 30 дней
- ✅ Создаёт **реализации** (20% заказов)
- ✅ Добавляет **частичные платежи** (30% реализаций)
- ✅ Распределяет все данные на разные даты для графиков
- ✅ costPrice = рандомная (10-110 для тестирования)

**Результат:** Полностью заполненная БД для тестирования

## 📊 Проверка данных после сида

### После `npm run seed`:

```sql
SELECT COUNT(*) FROM "Product";      -- Должно быть ~100 товаров
SELECT COUNT(*) FROM "Partner";      -- Должно быть 3 партнёра
SELECT COUNT(*) FROM "Price";        -- Цены для каждого партнёра
```

### После `npm run seed:demo`:

```sql
SELECT COUNT(*) FROM "Order";        -- Должно быть 50-100 заказов
SELECT COUNT(*) FROM "Realization";  -- ~10-20 реализаций
SELECT COUNT(*) FROM "RealizationPayment"; -- ~3-6 платежей
```

## 🔧 Кастомизация

### Изменить количество демо-заказов

**Файл:** `seed.ts` или `seed-demo.ts`

```typescript
const orderCount = Math.floor(Math.random() * 50) + 50; // 50-100, измени на нужное
```

### Изменить вероятность реализации

```typescript
if (Math.random() < 0.2) { // 20% шанс, измени на нужный
```

### Изменить базовые цены

**Файл:** `seed.ts`

```typescript
const BASE_PRICES: Record<string, number> = {
  MAGNET_MARBLE: 20,
  PLATE_MARBLE: 120,
  // Добавь или измени цены...
};
```

## ⚠️ Важное

1. **costPrice** задаётся один раз на группу товаров (`ProductGroup.costPrice`),
   а не на каждый товар отдельно - все товары одной группы стоят одинаково
   в производстве. Для реализаций в demo-режиме себестоимость позиции всё
   ещё генерируется рандомно, т.к. это просто тестовые данные.

2. **Реализации создаются только в demo режиме**

   - Production режим не трогает реализации

3. **Все старые заказы удаляются** при seed'e

   - Бэкапь БД перед seed'ом!

4. **Graphql не чистится** между seed'ами
   - Если видишь старые данные, очисти кэш браузера

## 📝 Примеры команд

```bash
# Инициализировать БД с базовыми данными
npm run seed

# Заполнить БД тестовыми заказами для проверки админ панели
npm run seed:demo

# Только загрузить товары (очистить заказы, но оставить партнёров)
npm run seed:production

# Очистить и переинициализировать
npm run seed:demo && npm run build

# С переменной окружения (альтернатива)
SEED_MODE=demo npm run seed
```

## 🚀 Production Deployment

```bash
# 1. Очистить старые данные
npm run seed

# 2. Вручную установить costPrice для групп товаров через UI (раздел "Группы") или SQL
UPDATE "ProductGroup" SET "costPrice" = <нужное значение> WHERE ...;

# 3. Создать партнёров и цены вручную через БД

# 4. Deploy
npm run build
npm start
```
